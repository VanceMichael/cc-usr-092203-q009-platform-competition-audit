# 经营主体退出协同

协调经营主体退出中的公告、清算、跨部门核验和登记决定。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块只校验资料边界，不预先实现业务流程。

`contracts/exit-case.schema.json` 描述退出案件资料结构，`fixtures/exit-case.json` 提供一件办理中的普通清算样例（主体与人员均为虚构）。

当前资料反映以下领域事实：

- 长期未经营主体退出时需区分简易注销、普通清算、强制退出与个体工商户停业
- 退出决定依赖公告、债权申报、税费结清、员工权益、诉讼限制、许可证与平台账户处置的逐项核验
- 公告异议、冒名申请、清算组变化和退出撤回必须保留历史，已注销主体恢复须有法定依据

## 领域模块

- `src/matters.js`：七类事项目录与四种退出路径的办理规则。同一事项在不同路径下阻断性不同（如税费欠缴不阻断强制退出，但阻断简易注销与普通清算）。
- `src/exitCase.js`：退出案件核心逻辑。部门回执按编号去重，重复或迟到回执只更新对应事项并留痕；公告异议、冒名申请、清算组变化、退出撤回均写入不可变历史；已注销主体恢复必须提供法定依据；登记人员在阻断事项全部解决后形成唯一有效决定，决定附逐项允许或拒绝的理由。
- `src/access.js`：角色视图。企业可查看自身待办与公开历史，但看不到未公开举报；债权人仅见公告信息、受控申报渠道和自己的申报记录；登记人员可见完整资料。

## 本地校验

运行 `npm test` 可确认样例资料能够被读取，并验证回执幂等、异议阻断、决定唯一、恢复依据、渠道受控与视图隔离等规则。仓库不保存账号、密钥、连接串或真实身份资料。
